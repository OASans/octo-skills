# Local audit storage

- Ledger: `~/.octo-memory/projects/<project-id>/ledger.json`; saved browser reports: the sibling `reports/` directory. These are outside installer-owned skill directories and remain through install, transcript cleanup, and checkout changes. Back up this directory to preserve deduplication across machines or disk loss.
- Project IDs hash the normalized full origin URL, shared by clones/worktrees; repositories without origin use their common Git directory. Origin renames require explicitly migrating the old ledger to the new ID after confirming identity; forks stay separate.
- Sessions are matched by recorded working directory or matching full origin metadata. Subagent, approval-audit, and the currently running session (when Codex supplies its ID) are excluded; `--exclude-session` adds other audit sessions to skip. These exclusions persist in the ledger across future invocations. `response_item` messages are the canonical representation; mirrored `event_msg` records and compaction records are ignored. Changed-working-directory turns are excluded. Unknown/malformed sources are reported, not marked processed.
- A processed record is identified by session ID plus a hash of its timestamp, role, and original message text. Filenames and date windows are not watermarks. The ledger retains message IDs permanently: overlapping windows skip old content while newly appended/resumed messages remain eligible. An unchanged copied file with the same session/event IDs adds no evidence. Retimestamped exports or summaries may be derivative evidence; the browser must not count them as independent recurrence.
- `prepare` snapshots visible messages through the current time and creates a pending packet; it does not mark them processed. Budget limits defer whole source batches without truncating them. Old complete messages outside the requested window remain unaudited. Tool results are omitted; supply relevant current owners explicitly and recover bounded original tool evidence locally when needed.
- The packet includes equivalent Markdown and ZIP artifacts plus a manifest with source IDs/line pointers. Review and redact sensitive content before upload; pattern-based redaction is incomplete. Keep raw transcripts, packets and reports local, never commit them.
- `finish` requires a completed browser GPT-6 Pro receipt, the expected attachment, explicit `AUDIT_COMPLETE` marker, and every session's first/last selected event IDs. Check the response for incomplete coverage before finishing. Atomic ledger replacement under a file lock records IDs and the preserved report together. Repeating finish is a no-op. Failed runs stay pending; resume collection rather than resending. A verified partial report must not be finished: resolve coverage before recording it.
- Held candidates remain in reports and need no transcript reread. Revisit them only on new evidence or explicit request; include the relevant saved report with `--prior-report <path>` in a new audit packet when requested. Topic writes are inspected separately; a ledger entry records completed analysis, not proof of promotion. Check existing topics and reports before retrying interrupted publication.
- Legacy `~/.octo-memory/<origin-repo-name>/short_term/*/*.md` captures are imported once by content hash, without deleting originals. Use `--legacy <directory>` to select the correct old store if names collide. Legacy provenance alone cannot establish independent recurrence. The old daily watermark is retired; existing knowledge topics stay active.
