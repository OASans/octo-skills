# Self-improve strategy research

Spend model effort on useful scientific thinking. Reduce repeated discovery, boilerplate,
unnecessary reads and demonstrated operational failures. Improve quality, tokens and latency
together; a faster invalid result is not an improvement.

## Serial cycle

Run from an octo-fin checkout with its `strategy-research-orchestrator` skill, canonical
`.codex/agents/strategy-research-worker.toml` and
`ai_tools/research/strategy_research/assignment_execution.md`. These own execution.
Keep researcher concurrency one: finish analysis and fixes before the next researcher.
Analysis and review agents are separate. Coordinate existing fleets rather than stopping them.

1. Dispatch one explicitly named `gpt-6.1-sol` worker without history inheritance. Give an
   existing reviewed-ready idea ID, scope and original budget. The worker owns startup,
   claim, workspace, supervisor, saved reviews, current admitted data pins, one well-built
   experiment, first-draft duplicate retrieval, frozen declaration, evaluation and closure.
   No source-intake re-review, variations, coordinator READY/GO or batch catalog barrier.
   Use normal automatic capacity waiting, cancellation and cleanup. Receive completion and
   exception notifications; occasional checks may unblock demonstrated trouble.
2. After every worker finishes, delegate a bounded read-only granular analysis of its
   original transcript and artifacts to an explicitly named `gpt-6.1-sol` agent. Include
   failed startup and HELP episodes. Complete the analysis below before the next researcher.
3. Main owns improvement decisions. For each operational error identify the cause and
   implement verified durable prevention in existing tools or instructions. Shared bugs
   belong to main; workers repair their own strategy code. External failures need bounded
   recovery and explicit limits. Scientific rejection is a valid result; operational trouble
   requests HELP. If no useful fix is evidenced, do not manufacture one.
4. Preserve retained work and budgets. Isolate changes in a detached worktree when needed
   under project branch policy; integrate finished fixes into the default branch. Run
   focused behavior regression coverage and required project gates; independently review
   consequential changes with `gpt-6.1-sol`. Commit and push major fixes promptly before
   the next round. Workers never write strategy tests.
5. Verify accepted closure, actual supervisor exit and resource cleanup. Resume recoverable
   work within its original budget. Justified operational takeover uses existing ownership
   and fencing controls, after authenticating previous-owner exit and accepted provenance.
   A separate bounded recovery may finalize accepted results after expiry; report it apart
   from the original failed episode. Never rerun accepted economics or conceal a restart.

Use current instructions and retained judgments. Do not hash auxiliary source-support
files, historical distinct-comparison evidence, branch history or documentation to decide
readiness or recovery. Preserve canonical source/review identity, exact active duplicate
proofs, ownership, frozen candidate/settings/data and accepted evidence.

Optional browser GPT-6 Pro analysis uses `tool-chatgpt-analysis` within the authorized scope.
Collect original transcripts, strategy code, settings, result artifacts and workflow docs;
ZIP and upload directly. Save its response and distinguish proposals from verified facts.
No sanitizer, exporter, deduplication system or reusable bundling tool.

## Analyze every original transcript

Authenticate the transcript against model, task, idea and assignment. Use original call and
result windows, normal-operation receipts and existing token accounting. Summary reports or
reviewer transcripts cannot substitute. Missing evidence stays unknown.

Retain one compact round report in the existing research artifact area containing:

- An exclusive, non-overlapping worker lifecycle partition and total. Separate pre-start
  preparation, post-exit reporting, coordinator fixes and other agents.
- A granular subtask table: action, start/end or elapsed time, attribution class, and exact
  transcript timestamps/lines or receipt identities. Show nested components without adding
  overlapping durations to the total. Tool wall time is not CPU usage.
- Skills read and used: list each observed skill name and source path, when and why it was
  read, and whether the transcript shows it guiding an action. Separate observed reads from
  demonstrated use; mark uncertain use unknown. Include repeated or irrelevant reads and
  their evidenced time/token cost where available. A listed or dispatched skill alone does
  not prove it was read. Include this inventory in the user-facing results report.
- Actual comparisons, refreshes, restarts, repairs and final outcome: duplicate, scientific
  rejection, VERIFIED or operational HELP. These are report categories, not new statuses.
- Authentic final cumulative worker tokens, separately from analysis/fix/review usage.
  Cached input is part of input. Do not sum cumulative snapshots or invent phase tokens.
- Quality evidence, warnings, concrete friction, fixes/commits, checks and remaining
  bottlenecks. Compare different ideas cautiously; one faster run does not prove causality.

Classify every subtask as PROGRAM (measured tool/process or receipt-bounded operation),
AGENT (directly evidenced agent work with supported timing), MIXED (inseparable computation,
agent/interface work or waiting), or UNKNOWN. Gaps between events are not thinking time.

Split at least instruction discovery, saved-source/API reads, activation, scientific
construction, native implementation, early probe, similarity retrieval, source comparison,
scientific declarations, mechanical publication, capacity wait, build, engine execution,
result projection, warning interpretation, checkpoints, finish/recovery and process cleanup.
Split further when evidence permits; mark absent stages not run and unsupported detail unknown.
Do not add historical inventory, store copies or private full-index rebuilds to ordinary research.

Rank improvements by evidenced benefit, quality and change risk. Name the existing interface
or instruction to change and observations to check next round. Mixed elapsed time is not an
estimate of savings. No manual metrics, prorated timing or accepted-trial reruns for comparison.

Preserve canonical ownership per distinct hypothesis, same-family concurrency, frozen
one-shot declarations, causal checks, provenance, trial accounting, admission gates,
mandatory raw IS Sharpe >=0.7 and visible data warnings. Early duplicate retrieval has no
Sharpe gate: correlation retrieves candidates; actual mechanism, timing and construction
must establish equivalence. Identical returns alone do not prove duplication.

Continue until the user stops, their limit is reached, executable supply ends, or a required
outside-scope decision prevents further work. Report retained HELP and exact next actions.
This is a host-driven cycle, not a promise of an unattended process after the turn ends.
